# Detection: Remote Authentication: SSH Login

| Field | Value |
|---|---|
| Tactic | Lateral Movement |
| Technique | T1021.004  Remote Services: SSH |
| Log Source | Filebeat (`filebeat-*`, `system.auth`) |
| Severity | Medium |

## Description
Surfaces successful SSH authentication events, particularly useful when correlated against prior reconnaissance activity from the same source.

## Attack Simulation
```bash
ssh vboxuser@192.168.56.104
```
Login succeeded, a brief interactive session was opened, then closed with `exit`.

## Detection Query
```kql
event.dataset : "system.auth"
```
Reusable copy in `queries/filebeat-auth-events.kql`.

## Why This Works
Filtering Filebeat's shipped `/var/log/auth.log` to `system.auth` isolates authentication-specific events (SSH/sudo) from general system noise, where login success/failure is recorded.

## Evidence
`screenshots/06-auth-log-monitoring.png`  19 `system.auth` events in a 15-minute window, timestamp-correlated with the SSH session.

## Recommended Response
See `playbooks/alert-triage-playbook.md`. Containment: enforce SSH key-based auth, disable direct root login, alert on successful logins from IPs seen scanning the host minutes prior.
